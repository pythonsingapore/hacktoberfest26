# Contributing to hacktoberfest26

Welcome, first-timers. Useful, reviewed work matters more than PR counts.

1. Read the README, this guide, the Apache-2.0 LICENSE, and the current open issues. Ask in an issue before taking a task; a maintainer may prefer an assignment or a different scope. Do not add a hello file unless the organizer opens an exercise for it.
2. Fork this repository and make a branch named for your task, such as `docs/clarify-setup`. Change only what the issue calls for. Do not include secrets, private data, copyrighted text you cannot license, or unreviewed generated content.
3. Check spelling, links and Markdown rendering. For a skill, check that the folder name matches the YAML frontmatter `name`, that `description` says what it does and when to use it, and that you can follow the steps on a sample input. See the [Agent Skills spec](https://agentskills.io/specification).
4. Open a PR against `pythonsingapore/hacktoberfest26` `main`. Explain the issue, changes, checks performed and any limitations. Link the issue if one exists. `Fixes #N` is only for a PR that fully resolves that issue.
5. Respond to reviews. A PR is a request, not a promise of merge or an official Hacktoberfest reward.

For the "add your own SKILL.md" exercise, read [EXERCISE.md](EXERCISE.md). Please create one folder under `skills/` with a descriptive lowercase-hyphen name and its own `SKILL.md`. The example is a model for structure, not text to copy. Scripts and extra assets are optional; avoid external dependencies for your first skill. If your skill proposes actions on someone else's data, include a clear safety boundary and require the user's approval.

Be kind in review. Explain concrete changes and thank contributors. A maintainer will triage duplicate or out-of-scope PRs.
